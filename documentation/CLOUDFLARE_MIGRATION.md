# Cloudflare hosting and legacy redirects
The canonical production website is https://princesstg-creations.com. The original Pages hostname https://princesstgcreations.pages.dev remains available. After its successful production deployment, the merchant authorized automatic redirects from the old GitHub Pages address. GitHub Pages publishes the redirect build; Cloudflare publishes the full website.

## 1. Preview and prepare
Cloudflare Pages project: princesstgcreations. Keep production branch main, output directory dist, default root, framework None. Set SKIP_DEPENDENCY_INSTALL=true as Text in both Production and Preview. Use this backward-compatible build command (works on main before merge, and the new PR branch):
```sh
if [ -f build-site.cjs ]; then node build-site.cjs cloudflare; else mkdir -p dist && cp -R index.html 404.html albums arts audioPlayer data images pages script styles dist/ && find dist -type f -name '*.bak' -delete; fi && rm -rf ./functions
```
The final removal is only in the Cloudflare temporary build workspace to avoid treating Firebase Functions as Pages Functions. The build script copies only the listed public assets and rewrites old-domain Open Graph and Twitter image/URL metadata and canonical links on HTML pages. Source pages are unchanged.

Allow both princesstg-creations.com and the original production hostname princesstgcreations.pages.dev in Firebase Authentication > Settings > Authorized domains. Add the exact trusted preview hostname if testing logins there. Review Google OAuth, verification links, newsletter and document sharing. Auth sessions and local-only preferences are origin-specific; sign in again, and migrate any important local-only data before cutover.
Review every Worker that validates Origin (store, verification, newsletter, sharing, etc.). The store routes the exact Cloudflare production origin to the live Worker; preview, local and legacy origins use the sandbox Worker. If needed, add only the exact approved preview origin and deploy the sandbox Worker; do not allow wildcard origins. Live mode rejects github.io and uses a separate production D1 database and Stripe credentials as documented in [CD Store Worker Setup](CD_STORE_WORKER_SETUP.md).

## 2. Music metadata Worker
Keep https://princesstg-song-share.transgirl1991.workers.dev/song/<id> URLs unchanged. The live Worker's implementation is not tracked in this repository, so inspect it in Cloudflare before cutover. Preserve slug parsing, database reads, escaped Open Graph and Twitter title/description/image tags, and any crawler response behavior. Change only its storefront base/destination and site-owned image URLs to https://princesstg-creations.com; the new destination should keep the original song ID (for example /audioPlayer/pages/song.html?id=<encoded-id>) and any supported query parameters. Do not replace the metadata response with a bare HTTP redirect. If the existing Worker targets an old GitHub HTML URL, the browser will reach Cloudflare after legacy redirects are activated; direct update avoids an extra hop. Verify old share links for multiple songs and check their HTML metadata without JavaScript plus browser navigation. Existing cached social previews may need re-scraping.

## 3. Automatic legacy publishing on main
GitHub Pages uses GitHub Actions. Every push to main runs **Update Audio Index and Publish Legacy Redirects** in `.github/workflows/update-audio-index.yml`. It preserves the existing audio-index generation and commit steps, runs the migration checks, builds with `node build-site.cjs legacy`, and publishes only `dist`. The workflow can also be run manually on main. No ENABLE_LEGACY_REDIRECTS variable is required. The separate legacy publisher was removed so another workflow cannot overwrite these redirects with the full website. The Cloudflare build continues to use `node build-site.cjs cloudflare`.
The legacy build replaces all public HTML with small redirect pages that retain their title/metadata and have an ordinary fallback link. The browser redirects only from the exact old site host and project path, retaining pathname, query and fragment; Cloudflare's own HTML URL normalization may remove .html. Unknown old URLs get the redirecting 404 page, then Cloudflare handles the path. Direct image/audio and other static asset URLs remain served from the legacy host so previously embedded media still loads; GitHub Pages cannot perform host-wide HTTP redirects. The no-JavaScript fallback preserves the known page path but cannot automatically preserve query strings/fragments. The real Cloudflare build has no redirect code injected.
Test old homepage, deep links, a song query URL, a document share link, a 404 and an image. Confirm the unrelated /poetry site is untouched. For rollback, revert the redirect-activation commit on main and rerun the restored website publishing workflow. The old ENABLE_LEGACY_REDIRECTS variable no longer controls publication.
Custom domain metadata: the build rewrites both legacy GitHub project URLs and the old Pages hostname in existing URL/image metadata and canonical tags across all published HTML. New song generation and runtime song metadata use the custom domain. GitHub legacy redirects go directly to the custom domain. Update the separate song metadata Worker manually as described above; its code is not in this repository. No redirects from pages.dev are required for this metadata-only change.
