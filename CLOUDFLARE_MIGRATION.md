# Cloudflare cutover (PR #28)
Do not activate the legacy redirect until the Cloudflare production deployment is working. Do not enable live payments during this migration.

## 1. Preview and prepare
Cloudflare Pages project: princesstgcreations. Keep production branch main, output directory dist, default root, framework None. Set SKIP_DEPENDENCY_INSTALL=true as Text in both Production and Preview. Use this backward-compatible build command (works on main before merge, and the new PR branch):
```sh
if [ -f build-site.cjs ]; then node build-site.cjs cloudflare; else mkdir -p dist && cp -R index.html 404.html albums arts audioPlayer data images pages script styles dist/ && find dist -type f -name '*.bak' -delete; fi && rm -rf ./functions
```
The final removal is only in the Cloudflare temporary build workspace to avoid treating Firebase Functions as Pages Functions. The build script copies only the listed public assets and rewrites old-domain Open Graph and Twitter image/URL metadata and canonical links on HTML pages. Source pages are unchanged.

Allow the production hostname princesstgcreations.pages.dev in Firebase Authentication > Settings > Authorized domains. Add the exact trusted preview hostname if testing logins there. Review Google OAuth, verification links, newsletter and document sharing. Auth sessions and local-only preferences are origin-specific; sign in again, and migrate any important local-only data before cutover.
Review every Worker that validates Origin (store, verification, newsletter, sharing, etc.). The store config now permits the Cloudflare production origin while remaining in test mode. If needed, add only the exact approved preview origin and deploy the sandbox Worker; do not allow wildcard origins. Live mode still rejects github.io: remove it from live Worker configuration and use a separate production D1 database and Stripe credentials as documented in workers/cd-store/README.md.

## 2. Music metadata Worker
Keep https://princesstg-song-share.transgirl1991.workers.dev/song/<id> URLs unchanged. The live Worker's implementation is not tracked in this repository, so inspect it in Cloudflare before cutover. Preserve slug parsing, database reads, escaped Open Graph and Twitter title/description/image tags, and any crawler response behavior. Change only its storefront base/destination and site-owned image URLs to https://princesstgcreations.pages.dev; the new destination should keep the original song ID (for example /audioPlayer/pages/song.html?id=<encoded-id>) and any supported query parameters. Do not replace the metadata response with a bare HTTP redirect. If the existing Worker targets an old GitHub HTML URL, the browser will reach Cloudflare after legacy redirects are activated; direct update avoids an extra hop. Verify old share links for multiple songs and check their HTML metadata without JavaScript plus browser navigation. Existing cached social previews may need re-scraping.

## 3. Activate only after production is verified
Merge PR #28 when the preview and other payment checks are ready. Verify the production Cloudflare deployment and new login, song playback, shared documents, images, checkout in sandbox, legacy song pages and the metadata Worker. Keep real payments disabled.
In GitHub repository Settings > Secrets and variables > Actions > Variables, create repository variable ENABLE_LEGACY_REDIRECTS=yes. Then in Settings > Pages > Build and deployment select GitHub Actions (not branch publishing). In Actions, choose Publish legacy website redirects, Run workflow on main. This workflow is opt-in and runs only on main. Subsequent main pushes publish the legacy redirect artifact. It does not deploy the real storefront or any checkout backend.
The legacy build replaces all public HTML with small redirect pages that retain their title/metadata and have an ordinary fallback link. The browser redirects only from the exact old site host and project path, retaining pathname, query and fragment; Cloudflare's own HTML URL normalization may remove .html. Unknown old URLs get the redirecting 404 page, then Cloudflare handles the path. Direct image/audio and other static asset URLs remain served from the legacy host so previously embedded media still loads; GitHub Pages cannot perform host-wide HTTP redirects. The no-JavaScript fallback preserves the known page path but cannot automatically preserve query strings/fragments. The real Cloudflare build has no redirect code injected.
Test old homepage, deep links, a song query URL, a document share link, a 404 and an image. Confirm the unrelated /poetry site is untouched. For rollback, set ENABLE_LEGACY_REDIRECTS=no and restore GitHub Pages source to main / (root); redeploy. Do not assume changing the variable alone replaces an already-published artifact.
Future custom domain: configure it in Cloudflare, Firebase and Worker allowlists, then update DEST and the fixed target origin in build-site.cjs, songlist.js, docs-links.js and the sharing Worker; add Cloudflare redirects for pages.dev if desired.
